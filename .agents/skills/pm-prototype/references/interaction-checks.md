# 交互路径与原型回归

用于新增流程、改控件、处理用户纠正或检查遗漏状态；小改动只检查受影响路径，不为每次任务生成整套矩阵。

## 先决定操作语义

- 找到真实入口与受影响对象：本人、单条记录、所选记录、整批或团队；展示名、作用范围和执行后果一致。
- 区分仅选中、暂存、确认提交与不可逆操作。是否可撤回依据实际能力，不发明撤销入口或额外审批。
- 明确成功、取消、关闭、返回、失败后停留或跳转位置；保持或清空哪些输入/选择有据可查。
- 只覆盖实际可达状态：初始未选择、已选择未提交、编辑回显、提交中、成功、校验失败、请求失败、空数据；权限、过期、并发等仅在业务适用时检查。

## 按场景执行

- 编辑：打开时回显全部现有值，锁定字段也应可见；修改可选项后验证剩余合法选择，错误指向真实失败字段，不用统一报错掩盖原因。
- 表单：错误提示不挤坏布局；取消/返回不意外提交；重复点击不产生误导的多次成功；失败后保留应保留的输入。
- 弹窗/抽屉：按对应项目规范检查关闭方式、遮罩、返回、正文高度及长内容滚动。不能把活动规则弹窗与购买、充值抽屉套用同一关闭策略。
- 移动端默认固定可视区域而非像素高度：页面容器占满设备当前可视屏幕，顶部导航固定，正文在剩余区域内部滚动；页面不随内容撑高。既有底部操作/本人栏固定并为正文留足空间，长弹窗限制最大高度并内部滚动。Tab、二级页及浏览器展示复用同一结构，检查动态视口、安全区、横向手势及长文本。隐藏滚动条只隐藏外观，不能用禁止滚动代替。具体按钮、栏位和例外按项目规范读取，不新增不存在的底部操作。
- 多角色/账单/奖励：切换已有示例与状态，检查字段显隐、条件回显、统计对象和结果文案。展示调整不等于创造新业务状态。
- 演示开关放在产品流程之外；不因原型可切换就假定线上有对应入口。

## 验证与交付

修过的路径和相邻路径至少各核对一次；声明实际使用的设备/视口/输入方式，不以鼠标拖动代替触摸手势验证。浏览器不可用时做代码检查并标明交互未验证。
保留内部“纠正→文件/位置→验证结果”清单；最终只简要交付文件链接、主要变化与未验证范围，不重复长报告。
