# 有参考图时：拆解与设计约束

参考图用于约束视觉和可观察交互，不是本产品业务政策来源。仅在有参考图时使用，不额外创建独立 Skill 或审批步骤。

1. **读图定位**：确认图片对应页面、区域及版本；多图分别标来源和用途。无法读取或模糊处说明未核对，不按相似页面补全。
2. **提取规范**：记录布局分区、信息层级、对齐、间距、配色、字体层级、组件形态和可见状态。截图色值/尺寸只能近似估计；精确值、字体名称和不可见行为需代码或其他来源核实，不从截图像素高度推断设备固定高度。
3. **确定边界**：简述“保留什么、调整什么、未知什么”；以用户要求、本产品规则和既有组件为依据。不为差异很小的修改强制输出大表或重复询问已经确认的布局。
4. **分清证据**：可见字段、文案、位置与选中状态属于截图事实；点击结果、滚动方式、权限、概率、周期、结算及发奖逻辑不能仅凭静态图确定。推测明确标注；会改变业务结果的未知项先查项目资料，仍无依据再问。
5. **处理冲突**：用户明确选择借鉴的视觉部分可以复用；竞品门槛、奖励和角色规则不自动继承。参考图与已确认规则冲突时保留本产品业务，说明需要调整的视觉位置，不静默拼接不同来源。
6. **预览核对**：按保留/调整清单对照预览，检查主要区域、组件一致性和适用状态；移动端沿用动态可视区域、固定导航/已有底部区、内部滚动的项目默认。用户批准前不把建议称已确认，不把截图还原称实际交互已验证。

视觉探索需要时才用 design-taste-frontend；普通参考图还原及局部修改不自动换风格。业务规则与交互闭环继续由现有 PM Skills 承接，交付仍遵守 pm-prototype 的预览流程及明确直接生成/修改的例外。
