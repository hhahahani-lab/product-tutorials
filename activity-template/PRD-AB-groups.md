# 模板 A／B 多组配置调整

## 一、规则组织

一条规则对应一个完整玩法。参与对象、统计周期、UTC+5 业务时区、统计口径、发奖方式及获奖上限为规则级配置。

发奖方式仅新增规则时可选择；规则创建成功后只读不可切换，沿用线上逻辑。D／E／F 新增时也按模板固定。

A 在规则内配置多个礼物组；B 在规则内配置多个消费档位。统计周期、参与对象或口径不同的玩法仍分别建立规则。

## 二、模板 A

- 每组填写一个礼物 ID 和触发数量，触发数量为正整数，同一规则礼物 ID 不可重复。
- 各组按自己的礼物数量独立累计、独立触发，不合并不同礼物 ID 的进度。
- 发奖方式在规则中选择全发／随机，各组独立配置奖励或奖池。
- 获奖上限按每组、每统计周期计算，0 表示不限，原有数量触发逻辑沿用。
- 可新增、删除礼物组，至少保留一组；保存规则后从「管理奖励」通过顶部横向 Tab 切换礼物组添加奖品、权重及其他奖励参数。

## 三、模板 B

- 规则级配置消费范围；选择指定礼物消费时填写对应礼物 ID。
- 每档填写一个正整数金币消费门槛，同一规则内门槛不可重复。
- 各档独立判定，分别配置奖励；本次不新增 F 的最高档／各档叠加模式，原 B 的达标触发逻辑沿用。
- 获奖上限按每档、每统计周期计算，0 表示不限。
- 可新增、删除消费档位，至少保留一档；保存规则后从「管理奖励」通过顶部横向 Tab 切换档位配置奖品。

## 四、奖励管理与列表

编辑规则配置组／档条件 → 保存 → 列表「管理奖励」 → 通过顶部横向 Tab 切换礼物组／消费档位 → 沿用现有奖励行配置并保存。

- 顶部横向展示全部组／档 Tab，仅展示当前 Tab 的奖励列表，每组展示礼物 ID 与触发数量或消费门槛、已配置奖励数量或未配置状态，以及独立的添加奖励入口。
- 顶部汇总总数、已配置数、未配置数。保存时检查所有组／档，漏配或参数错误提示具体组／档并滚动定位。
- 各组／档奖励分别保存，新增、删除和切换奖励类型时保留其他组／档输入，取消则不提交本次修改。
- 规则可先保存条件，未配置奖励的组／档须补齐奖励后才能作为可发奖配置使用，正式服务需校验配置完整性。
- 列表摘要自动展示组数／档数和每组／档获奖上限，无需手工填写摘要。

## 五、旧规则兼容

- 旧 A 的礼物 ID、数量及奖池回显为一组；旧 B 的消费门槛和奖励回显为一档。
- 不自动合并不同历史规则，也不在只打开页面时改写原数据。
- 新旧配置的真实计数、触发记录和奖励去重衔接由研发实施；后台 Demo 仅演示配置与本地保存。
