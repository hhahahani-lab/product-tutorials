# 活动模板 E 及参与对象配置 PRD

## 一、需求范围

1. 新增模板 E「任务累计活动值 → 抽奖」：用户通过送礼、竞技游戏消耗获得活动值，自动折算抽奖次数。
2. 全部模板新增「参与对象」配置。
3. 模板 E 的前端页面和数据接口统一封装，通过活动 ID 加载配置及业务数据，后续同类活动复用通用逻辑。

后台入口：[活动管理 → 活动配置列表](https://ylf-admin.meowclans.com/#/event/award)。

## 二、模板 E 配置

### 1. 基础配置

| 字段 | 配置规则 |
|---|---|
| 规则名称 | 必填，沿用现有字段 |
| 模板 | 新增选项「模板 E：任务累计活动值 → 抽奖」 |
| 参与对象 | 主播／全部用户，单选，默认全部用户；具体规则见第四节 |
| 规则说明 | 沿用现有字段 |
| 统计周期 | 固定展示「活动期累计」，不可修改 |
| 次数有效期 | 固定展示「活动期内有效」，使用所属活动的起止时间 |

### 2. 任务配置

任务类型支持多选「送礼任务」「游戏任务」，至少选择一项。两类任务获得的活动值合并累计。

#### 送礼任务

固定统计送出礼物。「礼物范围」单选：全部礼物／指定礼物。

选择「全部礼物」时，固定展示以下比例，不可修改：

| 礼物类型 | 活动值比例 |
|---|---|
| 常规礼物 | 100% |
| 幸运礼物 | 10% |

选择「指定礼物」时，支持新增、删除多组配置：

| 字段 | 配置与校验 |
|---|---|
| 礼物 ID | 每组可填写多个 ID；必填，校验 ID 有效，同一 ID 不可跨组重复 |
| 活动值比例 | 每组配置一个百分比，必填且大于 0；同组礼物使用同一比例 |

**送礼活动值＝礼物单价 × 数量 × 对应比例。**

- 指定礼物直接使用所在组比例，幸运礼物不额外乘 10%。
- 指定礼物模式新增「其他礼物也计入」开关，默认关闭。开启后，未指定的常规礼物按 100%、幸运礼物按 10% 计入；关闭则未指定礼物均不计入。
- 指定礼物优先使用所在组比例，每笔只计算一次，比例不叠加。原指定礼物配置默认关闭开关，计分结果保持不变。

#### 游戏任务

统计范围为全部竞技游戏，仅统计所选币种的消耗，不扣减中奖返还。

| 字段 | 配置与校验 |
|---|---|
| 消费币种 | 金币／金豆，多选，至少选择一项 |
| 金币折算比例 | 勾选金币时展示：消费 X 金币获得 Y 活动值；X、Y 必填且大于 0 |
| 金豆折算比例 | 勾选金豆时展示：消费 X 金豆获得 Y 活动值；X、Y 必填且大于 0 |

**游戏活动值＝对应币种消耗 × Y ÷ X。** 金币、金豆分别折算后合并累计。

### 3. 抽奖配置

| 字段 | 配置规则 |
|---|---|
| 次数兑换比例 | 每 X 活动值获得 1 次抽奖机会；X 必填且大于 0 |
| 发奖方式 | 固定展示「随机」 |
| 奖励配置 | 通过现有「管理奖励」入口配置 |

## 三、累计、精度与抽奖规则

### 1. 活动值累计与展示

- 仅统计活动期内符合参与条件的送礼和游戏消耗，活动值持续累计，不每日重置。
- 活动值最多保留 2 位小数。礼物、游戏折算配置须保证计算结果不超过 2 位小数；不符合时阻止保存，并提示调整折算配置。
- 页面向下取整，只展示整数；小数余值保留并持续累计，不因页面取整而扣除。
- 例如获得 1.5 活动值，页面展示 1；再获得 1.5，累计为 3，页面展示 3。

### 2. 次数兑换与使用

- 按实际累计活动值自动折算抽奖次数，不使用页面展示的整数计算。
- 不足一次的活动值继续累计至活动结束。
- 抽奖扣除对应的可用次数，可用次数不足时不可抽奖。

**可用次数＝⌊累计活动值 ÷ 每次所需活动值⌋－已使用次数。**

例如每 100 活动值获得 1 次，累计 250.5 活动值、已使用 1 次，则可用次数为 1 次，余值 50.5 继续累计。

### 3. 活动结束

活动结束后停止活动值累计及次数兑换，未使用次数失效，剩余活动值不结转。

## 四、全部模板新增参与对象

| 配置项 | 规则 |
|---|---|
| 适用范围 | 全部模板的规则配置 |
| 字段名称 | 参与对象 |
| 可选项 | 主播／全部用户，必填单选 |
| 默认值 | 全部用户 |
| 旧活动兼容 | 旧活动模板的参与对象默认全部用户 |

选择「主播」时，用户在活动期间需持续具有主播身份，参与时校验当前身份；失去主播身份后不可继续参与，包括任务累计、抽奖及奖励领取。

选择「全部用户」时，不限制主播身份。

## 五、模板 E 前端与数据接口封装

参考之前榜单模板的复用方式，将模板 E 对应的前端页面和数据接口统一封装。

### 1. 接入流程

后台配置模板 E 活动 → 前端传入活动 ID → 加载该活动的配置、用户进度和奖励数据 → 渲染通用任务及抽奖页面。

- 同一活动存在多条规则时，按规则区分配置、活动值、次数及奖励，避免混用。
- 礼物范围与比例、游戏范围、消费币种与比例、次数兑换比例、参与对象、活动时间及奖励均读取后台配置。
- 主题素材、标题等按活动替换；后续同类活动不再重复开发任务展示、活动值累计展示和抽奖逻辑。

### 2. 前端通用能力

- 按配置展示送礼任务、游戏任务及对应规则。
- 展示活动倒计时、用户累计活动值和可用抽奖次数；活动值按第三节规则展示整数。
- 展示后台配置的奖励，支持抽奖操作及结果反馈，抽奖后更新可用次数。
- 根据活动状态、参与资格及剩余次数控制操作；活动未开始、已结束、失去主播身份或次数不足时不可抽奖。
- 活动不存在或未开放时展示对应状态；数据加载失败支持重试，不将失败数据展示为 0。

### 3. 数据接口能力

| 数据／操作 | 内容 |
|---|---|
| 活动配置 | 按活动 ID 返回活动起止时间、所属规则、参与对象、启用任务、礼物范围与比例、游戏范围、消费币种与比例、次数兑换比例；提供服务端时间用于倒计时 |
| 用户进度 | 返回当前参与资格、实际累计活动值、可用抽奖次数 |
| 奖励数据 | 返回当前规则配置的奖励及展示信息 |
| 抽奖 | 校验活动状态、当前参与资格和可用次数，返回抽奖结果及更新后的可用次数；重复提交不得重复扣次 |

活动值累计、精度处理、次数折算、扣次和发奖由服务端统一处理，前端读取结果展示。失去主播身份后的参与限制由服务端同步校验。

具体接口路径和协议由研发设计，满足按活动 ID 复用模板 E 的要求。
