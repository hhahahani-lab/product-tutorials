# 活动模板优化与新增 PRD

后台入口：活动管理 → 活动配置列表 → 查看活动信息。

## 一、旧模板优化

### 1. 模板 A：多礼物组

原一条规则配置一个礼物 ID 和触发数量，调整为一条规则内配置多个礼物组。

| 配置项 | 规则 |
|---|---|
| 统计口径 | 送出礼物／收到礼物／收送双向 |
| 统计周期 | 单日／单周／单月／活动期累计 |
| 发奖方式 | 新增时选择全发／随机；创建成功后不可修改 |
| 礼物组 | 支持新增、删除，至少保留一组 |
| 每组礼物 ID | 一个有效礼物 ID，同一规则内不可重复 |
| 每组触发数量 | 正整数 |
| 获奖上限 | 按每组、每统计周期计算，0＝不限 |

各组独立累计和触发，不合并不同礼物 ID 的数量。每组独立配置奖励或奖池，操作流程见第二节「奖励管理」。旧规则回显为一组，保留原礼物、数量、奖励与上限，不自动合并历史规则。

### 2. 模板 B：多消费档位

原一条规则配置一个消费门槛，调整为一条规则内配置多个消费档位。

| 配置项 | 规则 |
|---|---|
| 统计口径 | 固定金币消费，只读 |
| 统计周期 | 单日／单周／单月／活动期累计 |
| 消费范围 | 常规消费／送全部礼物消费（含背包）／送指定礼物消费（含背包） |
| 礼物 ID | 选择指定礼物消费时填写，支持多个 |
| 发奖方式 | 新增时选择全发／随机；创建成功后不可修改 |
| 消费档位 | 支持新增、删除，至少保留一档 |
| 每档门槛 | 正整数金币数，同一规则不可重复 |
| 获奖上限 | 按每档、每统计周期计算，0＝不限 |

各档独立判定并配置奖励，原 B 的达标触发逻辑沿用。旧规则回显为一档，保留原消费范围、门槛与奖励。统一使用「档位」文案，移除无需运营填写的固定数量字段。

### 3. 模板 D：个人榜

旧规则默认个人榜。发奖方式固定全发、只读；统计周期支持单日／单周／单月／活动期累计。

| 配置项 | 规则 |
|---|---|
| 参与对象 | 全部用户／主播 |
| 统计口径 | 送出礼物／收到礼物，不支持双向 |
| 统计指标 | 按礼物个数／按金币价值 |
| 礼物范围 | 全部礼物／指定礼物 |
| 礼物折算 | 按金币价值时使用第二节的通用配置 |

个人榜按礼物个数时，支持同样的多组礼物 ID 和「其他礼物也计入」，但只按实际个数累计，不应用金币折算比例。切换指标不清空已填礼物和比例。历史个人榜的双向口径编辑时须重新选择送礼或收礼，不静默改为某一种。

### 4. 规则列表

列表调整为：规则 ID、规则名称、模板、参与对象、统计周期、规则摘要、奖励方式、操作。

- 移除独立的礼物 ID、数量阈值、消费门槛、奖励数等模板专属列，由规则摘要自动展示关键条件。
- 摘要最多两行，悬停查看完整内容，不新增人工维护字段；A 展示礼物组数，B／F 展示档数，D 展示榜单口径，E 展示任务及兑换比例。
- 模板 D 标注个人榜／亲密关系榜。奖励方式：A／B／C 展示全发或随机，D 固定全发，E 固定随机，F 展示仅最高档／各档叠加。
- 操作保留管理奖励、编辑规则、删除。

## 二、新增通用配置

### 1. 参与对象

全部模板新增「主播／全部用户」必填单选，默认全部用户；旧活动规则默认全部用户。

- 主播：活动期间需持续具有主播身份；失去身份后不可继续任务累计、抽奖或领取奖励。
- 全部用户：不限制主播身份。
- D 亲密关系榜按第三节固定参与条件展示，不把亲密关系用户加入其他模板的通用选项。

### 2. 礼物范围及折算

适用于 D 按金币价值的个人榜、D 亲密关系榜、E 送礼任务及 F。

| 配置项 | 规则 |
|---|---|
| 全部礼物 | 常规礼物固定 100%、幸运礼物固定 10%，只读 |
| 指定礼物 | 支持新增、删除多组，每组填写多个有效礼物 ID 和一个折算比例 |
| 折算比例 | 大于 0，并保证计算精度符合要求；同组礼物使用相同比例 |
| 礼物 ID 校验 | 同一 ID 不可组内或跨组重复 |
| 其他礼物也计入 | 仅指定礼物模式展示，默认关闭 |

**折算值＝礼物单价 × 数量 × 对应比例。** D 亲密关系榜称为亲密值，E／F 称为活动值。

- 指定礼物始终使用所在组比例，指定幸运礼物不额外乘 10%。
- 开关开启：未指定常规礼物按 100%、未指定幸运礼物按 10% 计入。
- 开关关闭：未指定礼物均不计入。
- 指定比例优先，每笔只计算一次，不叠加。
- 原指定礼物配置默认关闭开关；旧个人榜指定礼物回显为一组，比例默认 100%，未保存前不改写原配置。

A 按单个礼物数量触发、B 按消费门槛、C 按收集条件，保留各自的统计模型，不套用本节折算公式。

### 3. 时区、周期与精度

所有模板在统计周期后统一只读展示业务时区 UTC+5。日／周／月的边界沿用现有业务时间规则，统计最晚在所属活动结束时截止。

E、F 活动值最多保留 2 位小数，页面向下取整展示整数，小数余值保留参与计算；礼物与游戏兑换配置须保证计算结果不超过 2 位小数，不符合时阻止保存。榜单展示格式沿用原通用榜单规则。

### 4. 奖励管理

沿用「编辑规则 → 保存 → 列表管理奖励」流程。A／B／F 在规则中配置礼物组或档位条件，奖品在管理奖励中配置。

- 顶部横向 Tab 展示全部礼物组／档位，每个 Tab 对应独立奖励列表；组数较多时横向滚动，当前 Tab 保持可见。
- Tab 展示礼物或门槛、已配置奖励数／未配置状态；顶部汇总总数、已配置数和未配置数。
- 切换 Tab 保留输入；添加、删除和修改奖励类型不影响其他 Tab。统一保存全部组／档，取消不提交本次修改。
- 保存时校验全部 Tab，漏配或错误时自动切换到对应 Tab 提示；每组／档至少配置一项奖励。
- 规则可先保存条件，但奖励未配齐的规则不能作为完整发奖配置投入使用。
- 随机模式配置权重，可配置无奖励；全发模式不配置随机权重和无奖励。
- 奖励字段沿用线上：类型、奖励 ID、数量／等级／时长、适用性别、奖励说明。

**沿用线上限制：规则创建成功后，发奖方式只读不可切换。** 新增 A／B／C 时可选全发／随机；D 固定全发、E 固定随机、F 每档固定全发。

## 三、亲密关系榜（模板 D 扩展，独立排期）

### 1. 规则配置

在模板 D 中新增「榜单类型」单选：个人榜／亲密关系榜，旧规则默认个人榜。本部分独立排期，不阻塞旧模板优化与通用配置。

| 配置项 | 规则 |
|---|---|
| 参与对象 | 固定有有效 CP／密友关系的全部用户 |
| 统计周期 | 单日／单周／单月／活动期累计 |
| 业务时区 | UTC+5，只读 |
| 统计口径 | 固定关系双方互送礼物，只读 |
| 统计指标 | 固定亲密值，只读 |
| 礼物范围与折算 | 使用第二节通用配置，含背包礼物 |
| 发奖方式 | 固定全发，只读 |

### 2. 计分、排名与关系周期

- 接入现有亲密关系服务。每段 CP／密友关系独立计分，双方互送合并累计，关系外送礼不计入。
- 同一用户可随不同关系分别上榜，不限制关系数量；列表展示前 50 对，底部「我的」只展示本人排名最高的一段关系。
- 关系解除后不发奖励，榜单定时过滤失效关系，发奖时再次校验关系有效性。
- 重建关系按新的关系周期从零累计，不继承旧积分，也不恢复旧关系发奖资格。
- Top3、列表及「我的」均展示双方信息和关系亲密值。支持已配置周期切换、结算倒计时和在房跳转；格式化、同分排序与周期边界沿用已有榜单口径。
- 奖励沿用名次区间、奖励类型、资源、数量／等级／时长及适用性别配置。「不限」则双方各发一份；男／女仅发给符合性别的成员，双方均符合时分别发放。
- 按关系周期、统计周期、奖项和接收人去重，失败仅补发失败项。

排名单位、前 50 对、底部「我的」选取和关系周期处理属于固定业务规则，不作为独立配置字段或说明模块放入编辑表单。

### 3. 前端与接口封装

后台配置 D 亲密关系榜 → 前端传入活动 ID → 加载规则、周期配置、双人榜单、本人最高排名关系和奖励数据。

复用榜单页面与数据接口，支持双方信息展示、周期切换、结算倒计时和在房跳转；关系计分、关系有效性过滤、结算校验及双人发奖由服务端处理。主题素材、标题按活动替换。

## 四、新模板 E：任务累计活动值抽奖

### 1. 规则配置

| 配置项 | 规则 |
|---|---|
| 统计周期 | 单日／单周／活动期累计，原方案默认活动期累计 |
| 任务类型 | 送礼任务／游戏任务，多选，至少选择一项 |
| 统计口径 | 按启用任务只读展示送出礼物、竞技游戏消耗或两者 |
| 次数兑换比例 | 每 X 活动值获得 1 次抽奖机会，X 必填且大于 0 |
| 发奖方式 | 固定随机，只读 |
| 次数有效期 | 活动期内有效，只读 |

送礼任务采用第二节的礼物范围与折算配置，固定统计送出礼物。

游戏任务：

- 范围为全部竞技游戏，仅统计消耗，不扣减中奖返还。
- 消费币种支持金币／金豆多选，至少选一项。
- 每种币分别配置「消耗 X 币获得 Y 活动值」，X、Y 必填且大于 0。
- **游戏活动值＝对应币种消耗 × Y ÷ X。** 两种币及送礼任务折算后合并累计活动值。

### 2. 累计与抽奖

- 按所选统计周期累计实际活动值，自动折算次数；不足一次的余值在本周期内继续累计。
- 周期结束后未兑换余值清零，不跨周期结转；已兑换次数保留，活动期内可用。
- 每周期兑换次数＝⌊该周期实际累计活动值 ÷ 每次所需活动值⌋。
- **可用次数＝各周期已兑换次数之和－活动内已使用次数。** 计算使用实际值，不使用页面展示整数。
- 抽奖校验活动状态、参与资格及可用次数，扣除相应次数，返回结果及更新后的次数；重复提交不能重复扣次。
- 活动结束后停止累计和兑换，未使用次数失效。

### 3. 前端与接口封装

后台配置 E 活动 → 前端传入活动 ID → 加载任务配置、用户进度、可用次数及奖励 → 渲染通用任务与抽奖页面。

- 配置和数据按活动及规则区分，读取周期、任务、礼物比例、游戏币种与比例、兑换比例及奖励，不逐个活动写死。
- 通用页面展示任务规则、活动倒计时、本人活动值、可用次数、奖品及抽奖结果。
- 接口提供服务端时间、活动状态、参与资格、实际进度和抽奖结果；累计、精度、兑换、扣次与发奖由服务端处理。
- 主题素材、标题按活动替换，复用页面和业务逻辑；加载失败支持重试，不显示为进度 0。

## 五、新模板 F：送收礼达档奖励

### 1. 规则配置

| 配置项 | 规则 |
|---|---|
| 统计口径 | 送出礼物／收到礼物，单选下拉 |
| 统计周期 | 单日／单周／活动期累计 |
| 礼物范围与比例 | 使用第二节通用配置，符合范围的礼物合并累计 |
| 档位奖励方式 | 仅最高档／各档叠加，单选下拉 |
| 奖励档位 | 可新增、编辑、删除，至少一档 |
| 每档门槛 | 大于 0、最多 2 位小数，同一规则不可重复 |
| 发奖方式 | 每档固定全发，只读 |

编辑规则只配置档位门槛；保存后从管理奖励的横向 Tab 配置各档完整奖励，不配置与上一档的差额。

### 2. 达档与发奖

| 档位奖励方式 | 发放规则 | 发奖时间 |
|---|---|---|
| 仅最高档 | 每周期仅发最终最高达成档的完整奖励，各档不叠加 | 周期结算后发放，单日次日发放 |
| 各档叠加 | 每个达成档每周期只发一次；跨过多档时补齐尚未发放的达成档奖励 | 达档自动发放 |

- 未达最低档不发奖；超过最高档不重复发放已完成档位。
- 活动值按周期重新累计，不结转；活动结束时结算最后一个统计周期。
- 原有收礼提成正常发放，不并入活动奖励。
- 金币、金豆和个人装扮发至个人账户。
- 新增房间标签、房间封面框、房间背景图奖励，分别配置资源 ID 和时长。主播及普通用户均可接收。
- 发奖时未创建过房间的用户，跳过房间装扮，其他奖励正常发放；后续创建房间不补发该次跳过项。
- 房间装扮发至用户对应房间，沿用现有房间 ID 对应规则。
- 发奖失败仅补发失败项，不重复发金币或叠加时长；未创建房间的跳过项不作为失败重试。

### 3. 前端与接口封装

后台配置 F 活动 → 前端传入活动 ID → 加载任务配置、本人进度、档位及奖励 → 渲染通用达档页面。

- 展示当前活动值、最高达成档、各档门槛和完整奖励、达成及发放状态、距下一档所需活动值、周期倒计时。
- 配置与数据按活动及规则区分；计分、精度、达档、去重、发奖和失败项重试由服务端处理。
- 主题素材、标题按活动替换，后续同类活动复用页面与接口。
