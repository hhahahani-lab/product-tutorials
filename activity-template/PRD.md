# 活动模板优化与新增 PRD

后台入口：活动管理 → 活动配置列表 → 查看活动信息。

实施顺序：①旧模板基础优化及通用配置（含礼物往来对象）；②亲密关系共用进度与双人发奖，先接入 A；③新模板 E、F，F 复用关系任务能力。D 亲密关系榜随 CP 榜单活动独立推进配置与封装。

## 一、旧模板优化

### 1. 模板 A：多礼物组

原一条规则配置一个礼物 ID 和触发数量，调整为一条规则内配置多个礼物组。

- 新增「任务单位：个人／亲密关系」，配置及累计规则见第二节。
- 支持新增、删除礼物组，至少保留一组；每组配置一个礼物 ID 和触发数量，同一规则内礼物 ID 不可重复。
- 各组独立累计、触发，不合并不同礼物 ID 的数量；获奖上限按每组、每统计周期计算。
- 每组独立配置奖励或奖池，操作流程见第二节「奖励管理」。
- 旧规则打开后显示为一组，保留原礼物、数量、奖励与上限，不自动合并历史规则。

### 2. 模板 B：多消费档位

原一条规则配置一个消费门槛，调整为一条规则内配置多个消费档位。

- 支持新增、删除消费档位，至少保留一档；每档门槛为正整数金币数，同一规则不可重复。
- 消费范围在规则层统一配置；各档独立判定、配置奖励，获奖上限按每档、每统计周期计算。
- 旧规则打开后显示为一档，保留原消费范围、门槛与奖励。
- 将「挡位」统一修正为「档位」，移除无需运营填写的固定数量字段。

### 3. 模板 D：个人榜

- 礼物范围接入第二节通用配置，支持多组指定礼物及「其他礼物也计入」。
- 按金币价值统计时，使用通用折算比例；按礼物个数统计时，只累计实际个数，不应用金币折算比例。
- 切换统计指标不清空已填礼物和比例。
- 旧指定礼物配置打开后显示为一组，比例默认 100%，未保存前不改写原配置。

### 4. 规则列表

列表调整为：规则 ID、规则名称、模板、参与对象、统计周期、规则摘要、奖励方式、操作。

- 移除独立的礼物 ID、数量阈值、消费门槛、奖励数等模板专属列，由规则摘要自动展示关键条件。
- 摘要最多两行，悬停查看完整内容，不新增人工维护字段；A 展示礼物组数，B 展示档数，C 展示收集条件，D 展示榜单统计方式。

## 二、新增通用配置

### 1. 参与对象

除 A 亲密关系任务、D 亲密关系榜采用固定参与条件外，A～D 模板新增「主播／全部用户」必填单选，默认全部用户；旧活动规则默认全部用户。

- 主播：活动期间需持续具有主播身份；失去身份后不可继续任务累计或领取奖励。

### 2. 任务单位

第二阶段在模板 A 新增「任务单位：个人／亲密关系」，默认个人，旧规则默认个人；第一阶段不展示此字段。

| 配置 | 个人 | 亲密关系 |
|---|---|---|
| 参与对象 | 主播／全部用户 | 固定有效亲密关系双方 |
| 关系范围 | 使用「礼物往来对象」 | 仅 CP／CP及密友 |
| 统计口径 | 沿用原送出／收到／收送双向 | 固定双方互送，只读 |
| 进度与奖励 | 个人累计、个人达标获奖 | 每段关系共用进度，达标后双方按奖励配置获奖 |

- 同一笔互送礼物只计一次。每段关系的各礼物组分别累计数量；触发发奖和获奖上限按统计周期分别计算。
- 同一用户可随多段关系分别累计、达标和获奖，各段进度不合并。
- 关系解除后清除该段进度、取消待发奖励；重建关系从零开始，已发奖励不追回。
- 双方奖励使用现有适用性别配置。
- A 亲密关系任务使用随机发奖时，每段关系每次触发只随机一次，双方共享结果；抽中奖励时，按适用性别向双方各发一份，抽中无奖励时双方均无奖励。

### 3. 礼物往来对象

适用于 A 的个人任务及 C，B、D 个人榜不增加此项。选择关系限制时，仅统计礼物发生时符合条件的有效关系；未建立对应关系时不累计关系礼物进度。

| 配置项 | 规则 |
|---|---|
| 礼物往来对象 | 不限／仅 CP／CP及密友，单选下拉 |
| 默认值 | 不限，旧规则默认不限 |
| 送出／收到／双向 | 分别限定收礼方／送礼方／双方为所选关系对象 |

- 不限：按用户累计，不受关系变化影响。
- 仅 CP：绑定当前 CP 关系；解除后清除该关系进度、取消待发奖励，重建关系开启新进度。
- CP及密友：符合条件的礼物按用户共同累计；解除某段关系后，已有进度和待发奖励保留，后续与该对象的送收礼不再计入。
- 已发奖励不追回。

### 4. 礼物范围及折算

礼物范围适用于 D 个人榜，并供第三节亲密关系榜复用；个人榜按金币价值统计时展示折算比例，按礼物个数时不展示比例。

| 配置项 | 规则 |
|---|---|
| 全部礼物 | 常规礼物固定 100%、幸运礼物固定 10%，只读 |
| 指定礼物 | 支持新增、删除多组，每组填写多个有效礼物 ID 和一个折算比例 |
| 折算比例 | 正整数百分比，同组礼物使用相同比例 |
| 礼物 ID 限制 | 同一 ID 不可组内或跨组重复 |
| 其他礼物也计入 | 仅指定礼物模式展示，默认关闭 |

**折算值＝礼物单价 × 数量 × 对应比例。** 个人榜用于金币价值计分，亲密关系榜称为亲密值。

- 指定礼物始终使用所在组比例，指定幸运礼物不额外乘 10%。
- 开关开启：未指定常规礼物按 100%、未指定幸运礼物按 10% 计入。
- 开关关闭：未指定礼物均不计入。
- 指定比例优先，每笔只计算一次，不叠加。
- 原指定礼物配置默认关闭开关；旧个人榜指定礼物的处理见第一节「模板 D：个人榜」。

A 按单个礼物数量触发、B 按消费门槛、C 按收集条件，继续按数量、消费金额或收集条件计算，不使用本节比例。

### 5. 业务时区

A～D 模板在统计周期后统一只读展示业务时区 UTC+5。日／周／月的边界沿用现有业务时间规则，统计最晚在所属活动结束时截止。

### 6. 奖励管理

沿用「编辑规则 → 保存 → 列表管理奖励」流程。A／B 在规则中配置礼物组或档位条件，奖品在管理奖励中配置。

- 顶部横向 Tab 展示全部礼物组／档位，每个 Tab 对应独立奖励列表；组数较多时横向滚动，当前 Tab 保持可见。
- Tab 展示礼物或门槛、已配置奖励数／未配置状态；顶部汇总总数、已配置数和未配置数。
- 切换 Tab 保留输入；添加、删除和修改奖励类型不影响其他 Tab。统一保存全部组／档，取消不提交本次修改。
- 保存时检查所有组／档，漏配或填错时自动切换到对应标签提示；每组／档至少配置一项奖励。

## 三、亲密关系榜（模板 D 扩展，独立排期）

### 1. 规则配置

在模板 D 中新增「榜单类型」单选：个人榜／亲密关系榜，旧规则默认个人榜。列表模板列同步标注个人榜／亲密关系榜，奖励方式显示全发。

| 配置项 | 规则 |
|---|---|
| 参与对象 | 固定有有效 CP／密友关系的全部用户 |
| 统计周期 | 单日／单周／单月／活动期累计 |
| 统计口径 | 固定关系双方互送礼物，只读 |
| 统计指标 | 固定亲密值，只读 |
| 礼物范围与折算 | 使用第二节通用配置，含背包礼物 |
| 发奖方式 | 固定全发，只读 |

### 2. 计分、排名与关系周期

- 接入现有亲密关系服务。每段 CP／密友关系独立计分，双方互送合并累计，关系外送礼不计入。
- 同一用户可随不同关系分别上榜，不限制关系数量；列表展示前 50 对，底部「我的」只展示本人排名最高的一段关系。
- 关系解除后不发奖励，榜单定时移除已解除的关系，发奖时再次确认关系是否有效。
- 重新建立关系后从零累计，不带入原积分和待发奖励。
- Top3、列表及「我的」均展示双方信息和关系亲密值。
- 同一用户有多段关系获奖时，分别发放各段关系的奖励。

### 3. 前端与接口封装

后台配置 D 亲密关系榜 → 前端传入活动 ID → 加载规则、周期配置、双人榜单、本人最高排名关系和奖励数据。

- 支持周期切换、结算倒计时及在房跳转。
- 活动页面按配置展示双方信息、亲密值、排名和奖励；布局、视觉及交互可按活动独立设计，不限定为固定页面。

## 四、新模板 E：任务累计活动值抽奖

### 1. 规则配置

| 配置项 | 规则 |
|---|---|
| 参与对象、业务时区 | 使用第二节通用配置 |
| 统计周期 | 单日／单周／活动期累计，默认活动期累计 |
| 任务类型 | 送礼／游戏，可多选，至少一项 |
| 统计口径 | 根据所选任务，只读显示送出礼物、竞技游戏消耗或两者 |
| 次数兑换比例 | 每 X 活动值获得 1 次抽奖机会，X 大于 0 |
| 发奖方式 | 固定随机，只读 |
| 次数有效期 | 活动期内有效，只读 |

**送礼任务**

只统计本人送出的礼物。礼物往来对象、礼物范围和比例使用第二节配置。

**游戏任务**

- 统计全部竞技游戏的消耗，不扣减中奖返还。
- 金币／金豆可多选，至少一项；每种币分别配置「消耗 X 币获得 Y 活动值」，X、Y 均大于 0。
- 游戏活动值＝消耗数量 × Y ÷ X，与送礼活动值合并累计。

活动值最多保留 2 位小数，页面只展示整数，小数部分舍去但继续参与计算。比例配置导致计算结果超过 2 位小数时，不允许保存。

列表摘要展示任务及兑换比例，奖励方式显示随机。

### 2. 累计与抽奖

- 每满一次兑换门槛，自动获得 1 次抽奖机会。不足一次的活动值继续累计，本周期结束清零。
- 按实际活动值兑换，不按页面展示整数兑换；抽奖扣除可用次数。
- 已兑换次数不因关系解除而取消，可跨周期使用，活动结束后失效。

**关系解除后的进度**

| 任务配置 | 处理规则 |
|---|---|
| 仅送礼＋仅 CP | 清除未兑换活动值，取消待发奖励；重建关系从零累计 |
| 送礼＋游戏 | 保留已有活动值和待发奖励，游戏正常累计；与已解除关系对象的新送礼不再计入，重建后继续计入当前周期进度 |
| 仅送礼＋CP及密友 | 按第二节共同累计规则处理 |

已发奖励不追回。

### 3. 前端与接口封装

前端传入活动 ID，获取任务配置、本人进度、可用次数、奖品和活动倒计时，并调用抽奖、查询结果。

不同活动共用这些接口和业务能力，页面布局、视觉及交互独立设计。

## 五、新模板 F：送收礼达档奖励

### 1. 规则配置

| 配置项 | 规则 |
|---|---|
| 任务单位 | 个人／亲密关系，默认个人；按第二节任务单位规则处理 |
| 参与对象 | 个人任务选择主播／全部用户；关系任务固定有效关系双方 |
| 统计口径 | 个人选择送出／收到；关系任务固定双方互送，只读 |
| 统计周期 | 单日／单周／活动期累计，业务时区使用第二节配置 |
| 礼物往来对象 | 个人任务使用第二节配置 |
| 关系范围 | 关系任务选择仅 CP／CP及密友 |
| 礼物范围与比例 | 使用第二节配置，符合条件的礼物合并累计 |
| 档位奖励方式 | 仅最高档／各档叠加，下拉选择 |
| 奖励档位 | 可新增、编辑、删除，至少一档 |
| 每档门槛 | 大于 0、最多 2 位小数，同一规则不可重复 |
| 发奖方式 | 每档固定全发，只读 |

活动值＝礼物单价 × 数量 × 对应比例，最多保留 2 位小数。页面只展示整数，小数部分舍去但继续参与计算；比例配置导致结果超过 2 位小数时，不允许保存。

保存档位后，在「管理奖励」的对应标签下配置该档完整奖励，不填与上一档的差额。列表摘要展示档数，奖励方式展示仅最高档／各档叠加。

### 2. 达档与发奖

| 档位奖励方式 | 发放规则 | 发奖时间 |
|---|---|---|
| 仅最高档 | 每周期只发最高达成档的完整奖励 | 周期结束后发放，单日次日发放 |
| 各档叠加 | 每个达成档每周期发一次，一次跨过多档则各档都发 | 达档自动发放 |

- 活动值每周期重新累计，不结转；活动结束时结算最后一个周期。
- 关系任务每段关系分别累计和达档，双方按配置获奖。解除后清除该段进度、取消待发奖励，重建从零累计，已发奖励不追回。
- 新增房间标签、房间封面框、房间背景图奖励，配置资源 ID 和时长，主播及普通用户均可接收。
- 房间装扮发至用户对应房间。未创建过房间则不发该项，其他奖励正常发放，后续不补发。

### 3. 前端与接口封装

前端传入活动 ID，获取任务配置、个人或各段关系的活动值、最高达成档、各档门槛与奖励、发放状态、距下一档所需活动值及周期倒计时。

不同活动共用这些接口和业务能力，页面布局、视觉及交互独立设计。
