# 活动模板 F：送收礼达档奖励 PRD

## 一、玩法

用户在活动期间送出或收到指定范围的礼物，按比例累计活动值，获得达成档位的奖励。模板 F 独立配置，复用已有活动与奖励基础能力。

## 二、后台配置

| 字段 | 规则 |
|---|---|
| 规则名称 | 必填 |
| 模板 | 模板 F：送收礼达档奖励 |
| 参与对象 | 主播／全部用户，默认全部用户；主播须在活动期间持续具有主播身份 |
| 统计口径 | 送出礼物／收到礼物，单选下拉 |
| 业务时区 | UTC+5，固定只读展示 |
| 统计周期 | 单日／单周／活动期累计，使用所属活动的时间与业务时区 |
| 规则说明 | 沿用现有字段 |
| 礼物范围 | 全部礼物／指定礼物，单选 |
| 档位奖励方式 | 仅最高档／各档叠加，单选下拉 |
| 发奖时间 | 根据档位奖励方式固定展示，不单独配置 |

### 礼物与活动值

- 全部礼物：常规礼物比例固定 100%，幸运礼物比例固定 10%，不可修改。
- 指定礼物：支持多组，每组填写多个礼物 ID 和对应比例，同一 ID 不可组内或跨组重复。指定幸运礼物直接使用所在组比例。
- 指定礼物模式新增「其他礼物也计入」开关，默认关闭；开启后，未指定常规礼物按 100%、未指定幸运礼物按 10% 计入，关闭则均不计入。指定比例优先，每笔只计算一次，不叠加。旧指定礼物配置默认关闭开关。
- 活动值＝礼物单价 × 数量 × 对应比例。符合范围的礼物合并累计，按所选的送出／收到行为统计。
- 活动值最多保留 2 位小数，前端向下取整展示整数，小数继续累计。折算配置须保证计算结果不超过 2 位小数。
- 单日、单周统计在周期结束后重新累计；活动期累计持续至活动结束。周期之间不结转活动值，最晚在活动结束时结算当前周期。

### 奖励档位

编辑规则时支持新增、编辑和删除多个档位，仅填写活动值门槛；奖励配置与规则配置分离。每档包含：

| 字段 | 规则 |
|---|---|
| 活动值门槛 | 必填、大于 0，最多 2 位小数；同一规则不可重复 |
| 奖励列表 | 规则保存后从列表「管理奖励」进入，通过顶部横向 Tab 切换档位配置至少一项奖励；每档配置完整奖励，不配置与上一档的差额 |
| 奖励参数 | 按类型填写奖励 ID、数量、等级或有效天数 |

奖励沿用已有个人奖励类型，并新增房间标签、房间封面框、房间背景图，分别配置资源 ID 和时长。每档奖励全部发放，不使用随机权重或空奖。

### 奖励配置流程

编辑规则、配置档位门槛 → 保存规则 → 列表「管理奖励」 → 顶部横向档位 Tab → 按档新增／删除奖励行 → 统一保存。每档显示门槛及已配置奖励数量／未配置状态；顶部汇总配置进度，保存校验全部档位，自动切换到漏配或错误的 Tab 并提示。规则可先保存无奖励档位，未配置奖励的档位不可作为可发奖配置投入使用；正式服务需检查完整性。

## 三、达档与发奖

| 奖励方式 | 规则 | 发奖时间 |
|---|---|---|
| 仅最高档 | 每周期仅发最终最高达成档的完整奖励，各档不叠加 | 周期结算后发放；单日统计次日发放 |
| 各档叠加 | 每个达成档位每周期仅发一次，跨过多档时补齐尚未发放的达成档奖励 | 达档自动发放 |

- 未达最低档不发奖；超过最高档不重复发放已完成档位。
- 单日活动在活动结束时结算最后一个统计周期；活动期累计在活动结束后结算。
- 原有收礼提成正常发放，不计入本活动奖励。
- 金币、金豆和个人装扮发至个人账户。
- 主播与全部用户均可获得房间装扮。发奖时已创建过房间的用户，房间装扮发至对应房间；未创建过房间的用户不发房间装扮，其他奖励正常发放，后续创建房间不补发本次跳过项。
- 房间 ID 沿用现有用户房间对应规则（万圣节玩法为房间 ID＝用户 UID）。
- 发奖失败仅补发失败项，不重复发金币或叠加装扮时长；因未创建过房间跳过的奖励不作为发奖失败重试。

## 四、前端及接口封装

后台配置模板 F 活动 → 前端传入活动 ID → 加载任务配置、本人进度、档位及奖励数据。

- 通用页面展示活动值、当前最高达成档、各档门槛及完整奖励、达成与发放状态、距离下一档所需活动值、周期结算倒计时。
- 活动未开始、已结束、不符合参与身份及加载失败时展示对应状态；加载失败可重试。
- 配置和数据按活动 ID 及规则区分。计分、精度、达档、去重、发奖和失败项重试由服务端处理。
- 主题素材、标题等按活动替换，后续活动复用页面与接口逻辑。

## 五、万圣节玩法配置示例

选择主播、收到礼物、单日统计、指定礼物、各组比例 10%、仅最高档。配置 70,000／210,000／500,000／1,000,000／2,000,000／3,000,000 六档门槛及对应奖励，复用原活动的档位奖励配置。
