## 一、Inviter｜邀请侧

展示本人邀请码、累计已到账 Coins／Beans 及六项任务，支持查看任务说明、奖励记录和邀请侧 Rules。

### 1. 邀请与奖励

用户进入活动后，主动点击 Get invitation code 并确认获取。每位用户只能拥有一个邀请码。服务端校验账号和当前设备资格，通过后激活邀请人资格、占用当前设备并生成专属邀请码；失败不生成、不占用；可修正问题允许重试，已识别为重复用户的账号不得通过换机或换网重新取得资格。重复获取返回原邀请码，不重复激活；仅注册、登录或浏览活动不激活。

点击 Invite Friends 或 Share 前，须校验已获取邀请码及当前账号、设备资格。未获取时打开获取弹窗提示获取，不自动激活；确认并通过校验后继续本次邀请或分享操作。校验通过后，Invite Friends 复制带邀请人信息的活动链接，成功提示 Copied；Share 打开分享面板。复制不计分享奖励。

各任务奖励自动发放，无需领取。

| 任务 | 条件／计算方式 | 邀请人奖励 | 限制 | 发放时间 |
|---|---|---|---|---|
| 新人绑定 | 自动识别或填码绑定成功，通过资格校验 | 200 Beans | 每新人一次；每邀请人每日最多 10 次 | 绑定校验成功后 |
| 新人首充 | 绑定后 7 天内，账号首笔有效充值 Coins ≥14,000 | 1,400 Coins | 每新人一次 | 确认有效首充后 |
| 持续充值返利 | 有效充值 Coins ×5% | Coins | 每新人累计最多 140,000 Coins | 确认有效充值后 |
| 游戏返利 | 竞技游戏有效 Coins 投入 ×1% | Beans | 每新人每日最多 1,000、累计最多 20,000 Beans | 按 UTC+5 自然日汇总，次日发放 |
| 送礼返利 | 新人向任意用户送礼：常规礼物 Coins ×5%、幸运礼物 Coins ×0.5% | Coins | 暂不设上限 | 按 UTC+5 自然日汇总，次日发放 |
| 每日分享 | 收到渠道明确成功回调 | 200 Beans | 每邀请人每日一次 | 确认有效成功回调后 |

- 绑定奖励按绑定成功时间所属 UTC+5 自然日、服务端确认顺序计数，前 10 次产生绑定奖励；超出不发本项奖励、不补计、不顺延。待发或发放失败仍占用当日次数，重试不另占次数。该限制不影响合法绑定关系、新人任务及其他邀请人奖励。
- 充值、游戏、送礼返利仅计绑定后、注册后 30 天内的有效行为；首充固定奖单独按绑定后 7 天判断。
- 绑定前已首充或首笔不足 14,000，后续不能补做首充任务，但绑定后充值仍计其他充值奖励。首充固定奖不占持续返利上限。
- 持续返利按每新人累计向下取整，本次可发为累计整数应得减已发；待发占用上限。新人完成最高档不影响邀请人继续返利。
- 游戏、送礼按每新人、每奖励项当日汇总后向下取整，日内保留小数，小数不跨日结转。常规、幸运礼物返利合并取整。
- 游戏每日上限在 00:00 重置，累计上限不重置；待发整数应得占用累计额度，超出每日上限部分不结转。邀请人的返利上限不限制新人任务进度。
- 新人送给邀请人无额外返利，邀请人送给新人不计本项返利；同一行为可同时推进新人任务和邀请人返利。

### 2. 每日分享

Share 提供活动海报、本人邀请信息和可用渠道，也可复制链接、保存海报。只有成功回调计奖，打开面板、唤起渠道、复制、保存或返回 App 均不计。

跨日回调归服务端收到当天，同一事件不重复计奖；不受单个新人 30 天窗口限制。有效渠道待验证，不启用截图审核。

### 3. 奖励记录

按时间倒序分页，查询最近 30 个 UTC+5 自然日（今天及前 29 天），不影响历史累计已到账收益。时间精确到秒；游戏／送礼按统计日期判断查询范围，其他按奖励事件日期。

| 任务 | 记录内容 |
|---|---|
| 绑定 | 好友、绑定时间、奖励、状态 |
| 首充 | 好友、奖励、状态；未完成的剩余时间或不符合原因 |
| 持续充值 | 好友、事件时间、返利金额、状态 |
| 游戏／送礼 | 好友、统计日期、当日返利、状态、实际到账时间 |
| 每日分享 | 奖励时间、金额、状态 |

## 二、Newcomer｜受邀侧

### 1. 绑定邀请人

| 方式 | 流程 |
|---|---|
| 自动识别 | 打开邀请落地页 → 点击下载并复制邀请信息 → 下载注册、进入 App → 读取剪贴板 → 校验绑定 → 进入活动 |
| 手动绑定 | Bind Your Inviter → 输入邀请人的邀请码 → 确认 → 校验绑定 |

- 仅上线后注册、且注册未满 24 小时的新人可绑定；邀请人须更早注册。超时未绑定则新人任务失效，不再允许自动或手动绑定。
- 每新人只绑定一位邀请人；同一账号或已识别为同一用户的不同账号之间不得互邀，不得循环邀请或修改关系；重复识别、填码及回调不重复绑定和发奖。
- 自动识别和填码绑定均须校验双方 UID、Google／Apple 登录唯一标识、当前设备及已有用户／设备关联结果，并使用受邀人本次绑定请求的 IP 做受邀用户去重；同时确认新人资格、邀请人已激活及邀请码有效。全部通过才建立关系并发放绑定奖励；任一校验不通过则不绑定、不发奖，不替邀请人自动激活。可修正的问题允许在期限内重试，重复用户认定不因换机或换网解除，绑定期限不延长；设备规则见第四节。
- 剪贴板失败或拒绝读取不阻断注册，可改用填码；只识别本活动信息，不重复跳转。取消填写不提交，重新打开保留本次输入，绑定成功后清空。

### 2. 任务规则

- 三项任务仅累计绑定后、注册后 30 天内的有效行为，绑定前不补计，绑定不重启期限。
- 每档固定奖励、每档一次、奖励累加；达标后自动发放，无需领取。一次跨多档发全部未获的达标档位，最高档后不再新增本任务奖励。
- 展示邀请关系、剩余时间、累计已到账 Coins／财富 EXP，以及各任务进度、门槛、奖额和达标情况；未结束且未达最高档的任务可进入充值、游戏或送礼。
- 达标不代表到账，不设独立奖励记录；待发或失败由后台处理，不要求用户重做任务。

## 三、Ranking｜邀请人榜单

沿用[活动榜单通用规则](https://ws-gitlab.ha7mi.com/yaloka-changpin/prototype/-/blob/master/new-user-invitation/rules/activity-ranking-common.md)，本节仅写活动特有规则。

### 1. 周期与计分

仅 Daily、Weekly，无总榜。使用 UTC+5，日榜为自然日；周榜为周一 00:00（含）至下周一 00:00（不含）。

**积分＝周期内邀请人应得 Coins＋应得 Beans＋成功邀请人数×5。**

- 只计邀请侧六项奖励，包含分享；新人任务奖励、EXP、榜单奖品、Host 邀请奖励等不计。
- 绑定成功按不同新人加人数分，后续行为不重复增加；超出绑定任务日奖励上限的合法绑定仍计人数分，不产生对应的绑定奖励分。奖励按第一节取整、应用上限后的整数应得计分，日周榜分别归属周期，不使用历史累计。
- 分享可独立计分；重复事件、发放失败及重试不增减已确认应得积分。游戏、送礼归行为日及所属周，其他奖励归有效业务事件日期。

### 2. 奖励与结算

- 最终排名确认前，先完成周期内游戏／送礼返利计算；当日预估排名以最终结果为准。
- 锁榜前收到的有效迟到事件归原业务日计入；锁榜后迟到事件不补榜、不转入下一周期。

## 四、共用规则与配置

### 1. 账号、设备与风控

按 UID、Google／Apple 登录身份和设备识别多个账号是否属于同一用户；受邀账号之间另结合 IP 去重。已识别为同一用户的多个账号不得重复取得对应资格，也不得互相邀请；换设备或换网络不解除已有识别结果。

同账号可兼任邀请人与受邀人，分别计奖；关联多个登录方式不新增资格，与新 Host 邀请活动可同时获奖。

| 场景 | 规则 |
|---|---|
| 设备占用 | 同设备仅一个账号可参与，双方资格、设备占用及绑定须避免并发重复成功；设备关联只约束活动资格 |
| 受邀 IP | IP 是受邀用户唯一性识别维度之一；整个活动期间，同 IP 的不同账号按同一用户处理，仅一位可取得受邀资格。已判定重复的账号不能通过换网络重新取得资格；已成功绑定的账号正常换网不影响关系、进度及返利。仅限制受邀资格，不限制该 IP 下邀请人数量，也不要求双方 IP 不同，不以双方 IP 相同单独认定自邀 |
| 邀请人激活 | 主动获取邀请码时校验并占用当前设备；已有受邀资格的同一账号可继续获取邀请码，不新增账号资格 |
| 后续登录与释放 | 参与后关联此后登录设备，不追溯此前设备；退出、卸载、注销、期限结束均不释放原关联 |
| 其他账号 | 在关联设备注册则不得获得资格，换机不能绕过；仅登录的未参与账号不得在该设备参与，不扩散关联其历史设备 |
| 已参与账号遇设备冲突 | 保留关系及历史奖励，标记并交风控核验 |

绑定时服务端须校验非自邀，并确保账号、设备及受邀 IP 校验与占用不会并发重复成功。设备标识稳定性、重装重置和误关联恢复待评估，不增加手机号或实名要求。资格校验应先于绑定发奖；确认作弊可取消资格、封禁或追回奖励。

### 2. 统计口径

- 7 天、30 天分别为连续 168、720 小时，截止时刻不包含。绑定与交易同时发生时，以服务端确认顺序判断，须先绑定成功。
- 自然日为 UTC+5 00:00（含）至次日 00:00（不含）；窗口结束停止新增进度和奖励；仍符合发奖资格的已产生应得继续发放。

| 行为 | 计算基数 | 业务时间 |
|---|---|---|
| App 内购 | 实际到账充值 Coins，无渠道赠币 | 平台订单成功且 Coins 入账完成 |
| H5 充值 | basic Coins，排除 reward 赠币 | 平台订单成功且 Coins 入账完成 |
| 币商向用户充值 | 用户该笔实际到账 Coins，不反推 basic／reward 或美元 | 平台订单成功且 Coins 入账完成 |
| 竞技游戏 | 标记为可参与游戏的有效 Coins 投入，不扣中奖，不计 Beans 投入 | 下注成功且 Coins 扣除成功 |
| 送礼 | 实际成功送出的礼物 Coins，常规／幸运按对应任务折算 | 礼物订单成功且 Coins 扣除成功 |

混合充值按每笔基数相加；币商库存进货、薪资、普通转账及活动发奖不计充值。游戏、送礼不区分所用 Coins 来源，活动奖励 Coins 的符合条件消费也计入。

业务时间均取服务端记录，晚收到事件不改变原业务日及首笔充值顺序，游戏后续结算不改变投入日；分享单独按成功回调收到日计奖。

### 3. 异常与配置

- 应得与到账分开，累计已到账只计成功入账；仍符合发奖资格的失败奖励保留应得并重试，不能重复发奖。
- 不符合资格不计奖。封禁／注销仅影响当事账号，其全部未发奖励不再发放，不连带取消另一方奖励；永久封禁设备仍按资格校验处理。本期不处理充值退款后的重算追回。
- 奖励、门槛、币种、上限、参与范围、游戏、渠道、榜单周期和奖品使用全局配置，不区分新旧关系；仅对生效后的行为适用，不追溯重算历史进度或应得奖励，保留生效时间及变更记录。
- 后台可查邀请关系、资格／设备校验、原始事件、基数与进度、应得／已发金额、重试、系统消息及风控记录。
