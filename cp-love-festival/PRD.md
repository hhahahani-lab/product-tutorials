# Weekly CP PRD

## 1. 活动配置

| 项目 | 配置 |
| --- | --- |
| 活动时间 | 待定 |
| 时区 | 待定 |
| 页面文案 | 英文 |
| 榜单周期 | 周榜、月榜 |
| 页面 Tab | Ranking、Love Gifts、Hall of Love |

- 活动以 CP 关系为单位，展示双方头像和昵称，不展示 UID。
- 复用现有有效亲密贡献，活动积分、周期和奖励独立。
- 不改变原亲密值、关系等级、消费结算及原榜单。
- 不设置年度榜。

## 2. CP 榜单 Ranking

周榜统计当周活动积分，月榜统计当月活动积分。同一笔有效贡献可同时计入对应周榜和月榜。

```text
活动积分 = 有效亲密贡献 × 礼物活动倍率
```

- 普通合格礼物按 100% 计算。
- 指定活动礼物按配置倍率计算。
- 倍率仅影响本活动周榜、月榜。

| 榜单区域 | 展示内容 |
| --- | --- |
| Top3 | 名次、双方头像、双方昵称、活动积分 |
| 其他名次 | 名次、双方头像、双方昵称、活动积分 |
| My | 本人 CP 名次、双方头像、双方昵称、活动积分 |

未上榜时名次显示「-」，无积分时显示「0」。切换 Weekly、Monthly 时同步切换榜单、My 和倒计时。

### 榜单奖励

Rewards 入口放在倒计时与榜单之间，靠右展示。打开后默认展示当前榜单周期，也可切换 Weekly、Monthly。

| 奖励 | 周榜 | 月榜 |
| --- | --- | --- |
| 关系卡 | Top1–3 | Top1–3 |
| CP 头像框 | Top1–3 | Top1–3 |
| 徽章 | Top1–3 | Top1–3 |
| 座驾 | Top1–3 | Top1–3 |
| Banner | Top1，展示关系双方 | Top1，展示关系双方 |
| 开屏页 | — | Top1，展示关系双方 |

周榜、月榜结算次日自动发奖。

## 3. 活动礼物 Love Gifts

每款活动礼物单独统计 Top1 CP。统计值为该礼物的有效贡献，不使用周榜、月榜的加成活动积分。

- 支持切换礼物周期；当前周期显示倒计时，往期显示已结算结果。
- 默认选中首个礼物；点击其他礼物卡片后同步选中并打开大图。
- 礼物大图展示礼物、对应周期 Top1 双方、有效贡献和周期。
- 无 Top1 时显示空态，不补虚拟用户。

### 当前周期底栏

底栏仅在当前礼物周期展示，内容跟随选中的礼物：

- 本人及该礼物赠送最多的关系另一方；
- 双方头像和昵称；
- 该关系本期的有效贡献。

底栏不显示「My」和本人送出个数。点击底栏打开抽屉，按页面顺序查看全部活动礼物。

### 曝光奖励

Love Gifts 页面提供 Rewards 入口，展示两项权益：

| 权益 | 展示规则 |
| --- | --- |
| 活动页曝光 | 每款礼物当前周期 Top1 CP 展示在对应礼物卡片和大图 |
| 礼物面板曝光 | 选中活动礼物时展示该礼物上周已结算 Top1 CP Banner |

客户端礼物面板只写逻辑，不制作 Demo：

- Banner 按选中的礼物 ID 读取，不使用综合周榜 Top1。
- 点击 Banner 查看礼物大图、双方信息、有效贡献和结算周期。
- 切换礼物时同步更新 Banner。
- 非活动礼物或上周无获奖 CP 时不展示 Banner。

## 4. 往期荣誉 Hall of Love

Hall of Love 仅展示已结算结果，内部切换 Weekly、Monthly。

| 页面 | 展示规则 |
| --- | --- |
| Weekly | 最近一周突出展示 Top3；更早各周展示当周 Top1–3 |
| Monthly | 展示上月 Top10；Top1 突出，Top2–3 并列，Top4–10 列表展示 |

历史榜使用结算快照，双方昵称使用「&」连接，不显示当前倒计时。

## 5. 页面

页面顺序：标题 Weekly CP → 轮播头图 → Ranking / Love Gifts / Hall of Love 三个 Tab。

- 头图从页面顶部延伸至主 Tab，使用四张图片自动轮播。
- 头图 Top1 展示放在右下角，不显示昵称；皇冠居中。
- Ranking：周榜、月榜、倒计时、Rewards、Top3、列表及 My。
- Love Gifts：周期切换、倒计时、Rewards、礼物卡片及当前周期底栏。
- Hall of Love：Weekly、Monthly 往期获奖列表。
- 用户头像、礼物和奖励图使用本地 SVG 占位，不使用用户提供的个人图片。
- 页面仅保留必要标题和说明，不重复展示榜单名称、周期范围及倒计时标题。

交互 Demo：https://hhahahani-lab.github.io/product-tutorials/cp-love-festival/CP_Love_Festival_V8.html

## 6. 通用规则与待补配置

- 榜单同分、数值显示和发奖规则沿用[活动榜单通用规则](rules/activity-ranking-common.md)。
- 奖励叠加规则沿用[活动奖励通用规则](rules/activity-reward-common.md)。
- 加载失败使用 Toast；无数据时显示空态，不使用演示用户补位。
- 待补：活动时间、时区、活动礼物 ID、展示顺序及积分倍率。
- 待补：礼物 Top1 的统计主体、送礼方向和有效贡献口径。
- 待补：关系解除或更换后的积分、奖励和曝光归属。
- 待补：各名次奖励资源、有效期、发放对象及曝光时间。
- 待补：往期数据保留范围，以及赠送数量并列时关系另一方的选择规则。
