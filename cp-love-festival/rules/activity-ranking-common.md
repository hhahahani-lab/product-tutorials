# 活动榜单通用规则

- 标识：activity-ranking-common
- 产品：Yaloka / MeMe；适用于后续活动榜单设计，无单独约定时默认引用。
- 状态：2026-10-23 用户确认定稿，作为通用设计约定；未确认线上生效状态。
- 来源：本次南瓜派对讨论，用户明确要求作为榜单玩法通用规则记忆；配置出处见[南瓜派对PRD](../../../../outputs/万圣节活动PRD.md)。

## 默认规则

- 榜单页面不展示用户UID，覆盖Top3卡片、用户列表卡片及底部My区域；后续榜单默认沿用。UID仅作为内部识别或跳转参数使用。

- 按活动值降序，同分按服务端记录的达到该活动值时间排序，先到者优先；补算不回填为更早的业务时间。
- 榜单奖励在对应榜单周期结榜次日自动发放，日榜、周榜及总榜均适用。具体玩法引用本规则，只写差异。
- 奖励叠加沿用[活动奖励通用规则](activity-reward-common.md)，具体玩法仅写不允许叠加的例外。

1. 各榜单仅前50名上榜。
2. Top3独立卡片，其余用户列表卡片；展示用户头像、昵称、在房状态、活动值。在房显示可点击入口，跳转用户当前所在房间。
3. My固定底部，按同一规则展示本人信息、排名、活动值。
4. 未上榜或活动值为0，排名显示「-」；活动值0显示「0」。
5. 所有榜单活动值（含Top3、列表、My）：≤9,999,999原值展示；>9,999,999才缩写。统一除以1,000，保留1位小数、向下取整，单位小写k，不使用M等单位。
6. 二级Tab采用Daily、Overall；结算倒计时按天/时/分/秒独立格展示，避免重复日期信息。

切换榜单时同步更新奖品、倒计时、榜单及本人数据。倒计时以服务端周期截止时间和校准时间为准，每秒更新；归零后等待结算／周期更新，不代表已经锁榜或发奖。榜单 Rules 只展示该活动榜单规则。

| 原值 | 展示 |
| ---: | --- |
| 9,999,999 | 9,999,999 |
| 10,000,000 | 10000.0k |
| 12,345,678 | 12345.6k |

活动礼物、计分比例、奖励、时区和时间按各活动单独配置，不将南瓜派对的活动参数作为通用默认值。
