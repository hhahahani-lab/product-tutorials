# Yaloka 活动 Demo 页面默认约定

- 标识：activity-demo-common。
- 适用范围：Yaloka移动端活动页、H5及交互Demo；不扩展为后台、其他产品或所有弹窗的规则。
- 状态：长期设计默认。活动页约定于2026-11-16确认，抽奖展示于2026-11-23补充。
- 来源：用户审阅并修订的活动Demo通用规则表，四格倒计时组件参考图，以及用户确认复用的圣诞活动抽奖入口和结果弹窗。
- 使用：新建、修订活动Demo前读取，交付前逐项检查；当次明确特殊要求优先。

## 默认规则

| 项目 | 默认约定 |
| --- | --- |
| 导航 | 使用沉浸式导航，头图铺到顶部；左上角叠加返回按钮，不另设有底色的导航栏，不显示产品名或关闭按钮。 |
| Rule入口 | 位于头图下方与活动模块交汇处，贴右边缘；采用横向文字按钮，样式适配活动主题，不用卷轴图标。 |
| 活动礼物专区 | 放在玩法Tab上方，单个礼物主要展示图片和金币价格；计入规则统一放在专区底部，不逐个重复。 |
| 玩法说明 | 集中放在对应Tab标题下，合并参与方式、重置／有效期等必要说明；不在按钮下方重复提示。 |
| 档位与进度 | 档位门槛、当前进度和对应奖励放在同一模块。多档默认左右切换，如无特殊说明不全部直铺；箭头在卡片两侧垂直居中，不加底部圆点定位器。默认展示下一待达档位，可回看其他档位。 |
| 奖励展示 | 页面以奖励图＋天数为主，不重复写奖励名称、类型和自动发奖提示。VIP等级等必要识别信息可放在图内。轮次等信息不影响操作时不展示。 |
| 礼盒奖池及奖励构图 | 礼盒居中，奖励围绕礼盒展示。一般奖励优先和页面主图示结合，不拆成两部分，除非特殊说明。以图＋天数为主；默认不点击预览，不额外放“点击查看”、空奖概率或“Boxes may be empty”等空奖提示。玩法页说明聚焦参与方式，不以负面结果提示填充文案；实际抽奖结果仍如实反馈，不改变空奖配置，也不承诺必中奖。Rule暂不提供概率。 |
| 抽奖次数与操作 | 可用次数和下一次兑换进度同一行展示。进度格式为「未兑换余值／兑换门槛 → +1 chance」。操作按钮单独一行，并列显示单抽和一键全开。可用次数为0时两个按钮均置灰。可用次数为1时，一键全开等同单抽。 |
| 抽奖结果弹窗 | 有奖励时标题用 **Congratulations**，无奖励时用 **Sorry**。限时奖励上图下天数，单项居中，多项并排换行。同款可叠加奖励合并为一项，显示本次获得的累计天数。结果省略本次开启总次数，使用 **OK** 关闭。 |
| 抽奖空奖与记录 | 单次落空显示缺省图和 **Nothing inside**。多次抽奖省略空奖条目和次数，全部落空时仅显示 **Sorry** 和 **OK**。抽奖记录逐次保留。 |
| 记录入口 | 使用简洁的时钟图标，不用剪贴板、卷轴或Records文字按钮。各玩法打开各自的记录弹窗。图标保留可访问名称。 |
| 记录内容 | 采用紧凑文字排版，不带奖励图片。展示奖励具体名称、类型、天数、完整时间，必要时带档位；时间格式统一为`YYYY-MM-DD HH:mm:ss`，不单独标时区。仍按活动业务时区计算和显示，不改用浏览器时区。 |
| 榜单命名 | 活动榜单统一使用Ranking。 |
| 榜单奖励入口 | 放在榜单说明右侧、Top3上方，使用奖励图标入口，不做大块文字按钮。 |
| 榜单奖励弹窗 | 奖励带图展示；弹窗内可切换对应周期，如Daily／Overall。默认打开当前榜单周期，弹窗内切换不改变外部榜单；标题、关闭入口和周期切换保持可见，奖励内容内部滚动。 |
| 倒计时组件 | 使用Days／Hours／Mins／Secs四个独立方格横向排列；每格数字在上、单位在下。数字至少补足两位，如19／06／10／30，天数超过两位时完整展示。格子等宽、间距一致；配色及描边适配活动主题，不固定为参考图的粉色。默认不额外显示“Tree resets in／Event ends in／Daily ranking ends in”等标题，截止／重置含义通过所在玩法、当前周期及必要规则说明表达。 |

## 布局、时间及交互

- 页面容器、安全区、内部滚动、弹窗退出及焦点恢复沿用[移动端页面布局通用约定](mobile-page-layout-common.md)。沉浸式导航不改变固定视口、正文内部滚动的要求。
- 四格倒计时读取当前活动或所选榜单周期的截止时间，复用[活动榜单通用规则](activity-ranking-common.md)中的服务端时间校准、每秒更新和周期切换规则；归零不表示奖励已发放。
- 单位固定为上述四项，不改成长段日期文字或单行冒号倒计时。窄屏保持四格可读，不以极小字号挤压；具体截止时点从活动配置读取。
- 记录和奖励展示区分：记录需要具体奖励名称、类型及天数；主玩法奖励以图＋天数为主，不将两者混为一套字段。
- 抽奖兑换、扣次与一键全开的计算沿用[活动模板 E](https://github.com/hhahahani-lab/product-tutorials/blob/main/activity-template/PRD.md)。兑换门槛按当次活动配置。
- 图内VIP等级或其他必要识别信息保留；正式资源名未知时标明演示占位，不能把临时名称写成已确认资源。

## 替代关系与边界

- 本约定替代公共约定里Rule位于“头图标题右侧”的旧默认，改为头图下方交汇处右侧。
- 独立Rule／榜单奖励入口优先于旧的统一Rules／Rewards弹窗组织；其他关闭、滚动等通用交互仍复用[活动规则弹窗约定](activity-dialog-common.md)。
- 主题配色、头图构图、礼物价格、汇率、计入比例、档位、奖品、概率及进度重置方式按各活动需求确定，不固化为通用规则。
- 本文仅保存设计默认，不代表既有页面已完成同步；修改已有Demo时核对相关约定。

## 交付前检查

- 导航、Rule、活动礼物区及各Tab说明的位置与信息密度符合上表。
- 档位左右切换、时钟入口、文字记录和奖励弹窗周期切换实际可操作；弹窗内切换不影响外部榜单。
- 奖励图示与天数、记录具体名称／类型／天数、完整时间均对应同一奖项；没有重复提示和多余概率展示。
- 倒计时为四格布局；检查窄屏、长奖励名、零值和截止后的显示，不把静态数字当成真实倒计时已接入。
